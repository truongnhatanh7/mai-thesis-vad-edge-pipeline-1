1 · The big picture

Our goal is to watch a fixed surveillance camera and raise a flag when somebody moves in a way that normal people on that camera do not. Doing that straight from pixels would need a huge model. Instead we split the job into small, understandable stages and pass compact numbers between them.

Intuition Think of a security guard who first spots people, then follows each one with a finger, then judges how each person has just moved. The pipeline does the same: (1) find people and their body joints, (2) keep track of who is who, (3) judge the last second of each person's motion. Throwing the pixels away after stage 1 is what makes this cheap enough for an edge CPU, and also what makes the pipeline fragile: if stage 1 never sees a person, stages 2 and 3 never hear about them.

Where the compute and the accuracy go

our experiment On a Mac M4 Pro with one thread, the pose model takes 15–28 ms per frame, the tracker about 2.3 ms, and STG-NF about 0.7 ms per scored person-window; the pose model is about 90% of per-frame compute (EXP-001/results.md). The flow itself has only 616 weights (we recount this in section 8.5). So the speed knobs sit in front of the flow, and, as the next sections show, so does the accuracy.

What exactly does STG-NF score?

The unit is a window: the last 24 poses of one ID. Frame scores are assembled afterwards from window scores (section 9).

A frame contains an anomaly but no person was detected in it. What score does the frame get?

STG-NF's scoring code replaces frames without a person by the most normal value. An undetected anomaly is therefore a guaranteed miss. This is why coverage matters so much.

2 · Images as numbers: convolution, feature maps, resolution

2.1 A picture is a table of numbers

A grey-scale image is a grid of brightness values from 0 (black) to 255 (white). A colour image is three such grids stacked, called channels (red, green, blue). A ShanghaiTech frame is 856 × 480 × 3 = 1,232,640 numbers. A tensor is just the word for such a multi-dimensional table.

Intuition If you fed all 1.2 million numbers into an ordinary fully-connected layer with only 1,000 hidden units, you would need 1.2 billion weights, and a face learned in the top-left corner would have to be re-learned separately for the bottom-right. Vision networks avoid both problems with small, shared pattern detectors that slide over the image.

2.2 Convolution: a small pattern detector that slides

A convolution has a small grid of weights, the kernel (say 3 × 3). Put it on the top-left corner of the image, multiply each weight with the pixel under it, add the nine products: that is one output number. Slide one step right and repeat. The grid of outputs is a new image, a feature map, that is bright where the pattern in the kernel was found.

The math For a kernel K of size k×k, input I and stride s:
out[i, j] = Σa=0..k−1 Σb=0..k−1 K[a, b] · I[i·s + a, j·s + b] + bias
Output width = ⌊(W − k) / s⌋ + 1 (without padding). A layer has many kernels, each producing one output channel, and followed by a non-linearity such as ReLU. The kernel weights are the trainable parameters, and the same ones are used at every position.

2.3 Stacking layers: stride, feature maps, resolution

Early layers detect edges and blobs; later layers combine those into parts (a head, a leg) and then whole people. To let each cell see a bigger area, networks regularly use stride 2, which halves the width and height. A feature map “at stride 8” has 1/8 of the input's width and height, so each of its cells summarises an 8 × 8 patch of the (resized) input but with many channels describing what is there. Deep maps are small and rich in meaning; shallow maps are large and rich in position detail.

YOLOv8 uses three such maps, at strides 8, 16 and 32 verified in our code (yolov8-pose.yaml: “P3/8 – P5/32 outputs”). Everything a detector knows about a person must be carried by the cells of those maps.

2.4 Why small people vanish at 640 px

The frame is resized so that its long side equals the detector's input size imgsz. For an 856 px wide frame at imgsz 640 the scale is 640 / 856 = 0.748 (letterboxing keeps the aspect ratio). A person who is 50 px tall in the frame becomes 37 px tall inside the network. At stride 32 that is barely more than one cell; at stride 8 it is about 4.7 cells. Fewer cells means less evidence for the network to work with, and the training data contain few such tiny examples.

our experiment EXP-011/results.md measured this directly. Reference people are the released AlphaPose poses (box = min/max of keypoints), a person counts as “found” if a YOLOv8n-pose box with conf ≥ 0.25 overlaps it with IoU ≥ 0.3. At 640 px:

Caveat the authors wrote down The reference box is the tight min/max of the joints while a YOLO box is looser, which makes the IoU ≥ 0.3 rule harder for small people exactly where recall is near zero. So the numbers say “YOLO does not report a box that overlaps well with this person”, and may understate whether it detected something near them.
Deeper dive: why resolution costs so much compute

A convolution layer does work proportional to the number of cells it covers. Doubling the input's width and height gives 4× the cells and about 4× the multiply-adds. our experiment On the 4-vCPU VM (EXP-004, detector inference only): 18.4 ms at 480 px, 29.9 ms at 640, 48.5 ms at 800, 64.6 ms at 960. At 24 fps the frame period is 41.7 ms, so at 960 px 45–63% of frames are dropped (section 10.4). Resolution is therefore the biggest accuracy lever and the biggest deadline risk.

Receptive field. A cell in a deep map does not see only 32 × 32 input pixels: every layer enlarges the visible area, so the true receptive field of a stride-32 cell in YOLOv8 is far larger than 32 px. That is how a cell can recognise a whole person. For tiny people the problem is not that the context is missing but that the person is only a handful of pixels and a few cells.

Check yourself

A feature map at stride 32 comes from a 640 × 640 input. How many cells per side does it have?

640 / 32 = 20. The three YOLOv8 maps are 80 × 80, 40 × 40 and 20 × 20 for a square 640 input, i.e. 8400 candidate cells in total.

A person is 40 px tall in the 856 × 480 frame; imgsz is 640. About how tall is she inside the network, and how many stride-32 cells is that?

40 × 0.748 ≈ 30 px, and 30 / 32 is less than one cell of the coarsest map. The measured recall for the 32–48 px bin at 640 px is 0.7%.

Why can the same 3 × 3 kernel find a pattern anywhere in the image?

Weight sharing is the defining trick of a convolution: few parameters, and the detector responds to the pattern wherever it appears.

3 · Single-stage pose: YOLOv8n-pose

“Single-stage” means one network looks at the whole frame once and answers everything at the same time: where the people are, how sure it is, and where each of 17 body joints is. “n” means nano, the smallest member of the family, small enough for an edge CPU.

3.1 Backbone, neck and heads

Intuition Backbone = the eyes: turns pixels into feature maps of decreasing size and increasing meaning. Neck = a meeting room where meaning-rich coarse maps and detail-rich fine maps swap information. Heads = three small answer-writers, one per scale, that read their map cell by cell and write the answers. Small people are answered by the fine (stride 8) head, big people by the coarse (stride 32) head.

verified in our code The three headline blocks, verified in the installed Ultralytics 8.4.201:

  • C2f blocks do most of the feature extraction; SPPF ends the backbone with a cheap way to widen the view.
  • The neck is an FPN (top-down: upsample + concatenate with the shallower backbone map) followed by a PAN (bottom-up: a stride-2 convolution + concatenate with the neck map above), the yaml's two halves.
  • The Pose head subclasses Detect and adds one branch. For each of the three scales and for every cell it has three small convolution stacks: cv2 (box: 4 × 16 = 64 numbers), cv3 (class score: 1 number, since nc: 1, the person class) and cv4 (keypoints: 17 × 3 = 51 numbers).
A small correction to a common picture Older YOLO versions had a separate “objectness” output. YOLOv8 does not: Detect has only the box branch (cv2) and the class branch (cv3). With a single class, that class score is the person confidence we later threshold at 0.25.

3.2 Anchor-free grid prediction

Every cell of every map is a candidate. A cell does not say “a person is here” but “a person is around me, and this is where his box edges and joints are relative to my centre”. There are no pre-drawn template boxes, hence anchor-free. For a square 640 × 640 input there are 80² + 40² + 20² = 8400 candidate cells. (Our 856 × 480 frames are padded to a rectangle by Ultralytics, so the real count is smaller from paper / docs.)

The math (verbatim from kpts_decode) For a cell with integer indices (i, j), the anchor point is the cell centre a = (i + 0.5, j + 0.5) in stride units. A raw keypoint output r becomes a pixel position
x = (2·rx + (ax − 0.5)) · stride     y = (2·ry + (ay − 0.5)) · stride     visibility = σ(rv)
so one cell can place a joint up to several cells away from itself. A box side is stride × E[d], where d is a 16-bin distribution (DFL): E[d] = Σk=0..15 k · softmax(logits)k (the softmax). The 17 visibility numbers pass through a sigmoid.

3.3 Many candidates, one person: threshold and NMS

Neighbouring cells all want to claim the same person, so the network yields dozens of nearly identical boxes per person. Two filters clean this up. The confidence threshold throws away weak boxes. Then non-maximum suppression goes through the rest from best to worst: keep the best box, delete every remaining box whose IoU with it exceeds the IoU threshold, repeat.

verified in our code Our detector cache (detcache.py) runs Ultralytics with conf = 0.01, iou = 0.7, imgsz 640 and keeps everything with confidence ≥ 0.01 (at most 300 per frame). The gate c is applied later in replay.py: only detections with confidence ≥ c (default 0.25) go on to the tracker. That is why one cache can serve every gate value.

3.4 Why the nano pose model misses small people

  1. Too few cells. Section 2.4: below about 64 px there is little to look at. our experiment EXP-011.
  2. Training labels. from paper / docs The pose model is trained on COCO person-keypoint annotations. Annotators label joints mostly for people large enough to see them; tiny and heavily occluded people typically have no keypoints. The network is then rewarded for not being confident about them, so their class score stays low. A person detector trained only on boxes has no such restriction. We did not test this explanation directly; the following results are consistent with it:
    • our experiment A plain YOLOv8n person detector plus RTMPose on the same frames reaches anomalous-frame coverage 0.915 (vs 0.674) (EXP-016). The authors attribute the gain mainly to poses being produced for every tracked box with no pose-confidence gate.
    • our experiment Fine-tuning YOLOv8n-pose on ShanghaiTech training frames, with the released AlphaPose poses as labels, lifts anomalous-frame coverage from 0.674 to 0.952 and AUC from 68.53 to 80.28 at no extra inference cost (EXP-013), but is worse on a different dataset (UBnormal −4.1): site adaptation, not general improvement.
Deeper dive: what the training loss rewards

from paper / docs YOLOv8's training adds several terms: a box loss (IoU-type plus the DFL loss), a classification loss (binary cross-entropy against how well the predicted box matches the labelled one) and, for pose, a keypoint-location loss plus a visibility loss. A task-aligned assigner chooses, for each labelled person, the few cells that already predict that person best, and only those get box and keypoint targets. A labelled person therefore pulls a handful of cells towards a high score; a person with no label is treated as background and pushes all nearby cells towards zero. That is the mechanism behind “pose labels are missing for small people, so the model learns to ignore them”.

4 · The top-down alternative: person detector + crop + RTMPose

Intuition Single-stage: one network does everything and has to juggle “is that a person?” with “where is her left elbow?” for people of every size. Top-down: split the work between two specialists. A person detector only draws boxes (an easier task, with plenty of training labels even for small people). Then every box is cut out and resized to the same size and a pose network places the joints in that fixed-size crop. The pose network never has to think about scale.

4.1 Our top-down pipeline

verified in our code topdown.py and rtmpose.py (EXP-015/016):
  1. A YOLOv8n detector, person class only, finds boxes (confidence ≥ 0.01 cached, gate 0.25).
  2. BoT-SORT tracks the boxes (section 5), so every box has an ID.
  3. For each box: the box is widened to the 192:256 aspect and scaled by 1.25, then cut out with one affine warp to a 192 × 256 crop (black outside the image).
  4. The crop is converted to RGB and standardised with the model's own mean and std, then goes through RTMPose (the -s or -t variant, official OpenMMLab ONNX export).
  5. The network outputs, for each of the 17 joints, two vectors: simcc_x of 384 scores and simcc_y of 512 scores. The joint position is the position of the highest score, divided by 2, mapped back to the frame; its confidence is the smaller of the two peak heights.

The keypoints come out in COCO-17 order, the same as the released AlphaPose files (checked in EXP-015), so STG-NF can read them unchanged.

4.2 SimCC: finding a joint by classification

Classical pose networks output a heatmap per joint: a small 2-D image that is bright near the joint. The position is the brightest spot, but the spot's resolution is limited by the heatmap size (typically a quarter of the crop). SimCC (“simple coordinate classification”) treats the coordinate as a classification: cut the x axis into many fine bins and the y axis too, and let the network score every bin.

The math Joint k in a W×H crop with split ratio r = 2:
simccx ∈ ℝW·r = ℝ384,   simccy ∈ ℝH·r = ℝ512    x̂ = argmax(simccx)/r,   ŷ = argmax(simccy)/r    score = min(max simccx, max simccy)
Cost of the output layer per joint: W·r + H·r = 896 numbers, against (W/4)·(H/4) = 48 × 64 = 3072 for a quarter-resolution heatmap, and the precision is half a pixel instead of four. The last equation (the score) is exactly what our rtmpose.py does verified in our code.

from paper / docs In the paper, RTMPose pairs a CSPNeXt backbone with a head that applies a gated attention unit (GAU) to the joint-wise features before the two linear layers; it is trained with a soft-label classification loss (Gaussian-smoothed targets). We did not verify these details in our code; we only run the exported networks.

4.3 What the experiments say

our experiment Oracle-box experiment (EXP-015): take the boxes and tracks of the released AlphaPose poses (so the right people are found and tracked), but re-estimate the keypoints with a light model.

Reading: with the right people found and tracked, any of these small pose models reaches 85–86 AUC, even YOLOv8n-pose run on crops (84.99). Deeper dive: why not simply use the oracle pipeline?

The real top-down result (80.5–83.1) recovers most, but not all, of that gap, at a CPU cost that does not fit a 24 fps deadline on the VM.

5 · Tracking: who is who from frame to frame

Intuition STG-NF judges how one person moved over one second. For that we need, in every frame, to know that the person at the left is the same person as in the previous frame. The tracker maintains a list of “tracks” (one per person, each with an ID), and every new frame does three things: predict where each track should be now, match those predictions with the new detections, and update or create or retire tracks.

5.1 Comparing boxes: IoU

To ask “is this new detection the person I was following?” we need a similarity between boxes. Intersection over union divides the area the two boxes share by the area they cover together. Identical boxes give 1; disjoint boxes give 0. The matching cost used below is 1 − IoU.

IoU(A, B) = area(A ∩ B) / ( area(A) + area(B) − area(A ∩ B) )

5.2 Predicting where a person will be: the Kalman filter

Detections are jittery (the box shakes by a few pixels even when the person stands still) and sometimes absent. A Kalman filter gives a smoother estimate and a prediction for frames without a detection.

Intuition You have two noisy opinions about where the person is: your physics guess (“she was here moving this fast, so she should be there”) and the measurement (“the detector says she is there”). The Kalman filter averages them, weighting each by how certain it is. If the measurements are very noisy it trusts physics more; if the person may change speed suddenly it trusts the measurement more. The weight is called the Kalman gain and is recomputed each frame. While no measurement arrives the filter just keeps predicting, and its uncertainty grows.
The math (constant-velocity model) State s = (position p, velocity v). Each frame:
predict:   s ← F s,   P ← F P Fᵀ + Q     update:   K = P Hᵀ (H P Hᵀ + R)−1,   s ← s + K (m − H s),   P ← (I − K H) P
with F = [[1,1],[0,1]] (position += velocity), H = [1, 0] (we measure only position), m the measurement, R the measurement noise and Q the process noise (how much the speed may change). In 1-D the update is p ← p + K·(m − p) with 0 ≤ K ≤ 1.

verified in our code Ultralytics' BoT-SORT uses a Kalman filter on the box itself: state (centre x, centre y, width, height) plus their four velocities, a constant-velocity model with the box as a direct observation (KalmanFilterXYWH, trackers/utils/kalman_filter.py).

5.3 Matching tracks and detections

Now every track has a predicted box and every detection a measured box. Build a table: rows = tracks, columns = detections, cell = cost 1 − IoU. A greedy strategy picks the lowest cell first, strikes out its row and column, and repeats. That can be fooled: taking the single best pair may force an awful pair elsewhere. The Hungarian algorithm finds the assignment with the lowest total cost. Pairs whose cost is above a limit (BoT-SORT: match_thresh = 0.8) are left unmatched.

verified in our code matching.linear_assignment in Ultralytics uses lap.lapjv with a cost limit, a fast Hungarian-type solver.

5.4 What BoT-SORT adds

  • Two-stage association (from ByteTrack) verified in our code. First match tracks to high-score detections (score ≥ track_high_thresh). Tracks left over get a second chance against low-score detections (between track_low_thresh and track_high_thresh), matched on IoU only with limit 0.5. The idea: a person half hidden behind a pole gets a low score, but should still keep her ID.
  • Camera-motion compensation (GMC) and optional ReID appearance matching. verified in our code Our replay.py turns both off (gmc_method='none', with_reid=False): the camera is static and no images are given to the tracker.
  • Birth thresholds. verified in our code replay.build_tracker(c) sets track_high_thresh = new_track_thresh = c and track_low_thresh = min(0.1, c/2). Default c = 0.25.
A consequence worth knowing verified in our code replay_video already removes every detection below c before calling the tracker (above = frame["conf"] >= c). Since the tracker's low-score band lies below c, the second (low-score) association stage never has anything to match in our replays. Lowering c is the only way to feed it, and EXP-003 found that this never helps (section 10.3).

5.5 Why gaps matter: from tracks to windows

STG-NF needs 24 poses of one ID. verified in our code split_pose_to_segments cuts a track into windows of seg_len = 24 consecutive recorded poses, starting a window at every recorded pose at test time (stride 1; stride 6 at training time), and keeps a window only if is_seg_continuous says so: for a window starting at frame f, at least 24 − missing_th = 22 of its recorded poses must fall in the real frame range [f, f + 24). In plain words: at most two frames may be missing; the missing frames are not interpolated, they are simply skipped, so the window's time axis is slightly compressed.

A track needs at least 25 recorded poses to give any window (the number of windows is n − 24 at test time).

our experiment Why it hurts our pipeline: the edge pipeline produced 876 tracks / 69,984 poses with a median track length of 60.5 frames, against 1,415 tracks / 187,021 poses and 117.5 frames for the released AlphaPose + PoseFlow poses. That gives 50,091 scorable windows instead of 144,714 (EXP-001/results.md). And when a slow CPU drops 40% or more of the frames, almost every window misses more than two frames and nothing is scored at all (EXP-009 lead review: AUC 0.5). The pose-filling methods of section 10.5 exist to repair exactly this.

The score of a window is written onto the frame start + 12 (the middle; the “paper” variant, which needs 12 future frames) or start + 23 (the last frame; our causal “live” variant), see section 9.

Deeper dive: a few details of the Ultralytics tracker
  • A new detection that matches nothing and has score ≥ new_track_thresh starts an unconfirmed track. It becomes a normal track (and starts being output) only if it is matched on the very next frame (cost limit 0.7); otherwise it is deleted. This kills one-frame false alarms. (Frame 1 is the exception: its tracks are active at once.)
  • A tracked person who is not matched becomes lost but is kept, still predicted by the Kalman filter, for track_buffer = 30 frames. If a detection matches a lost track within that time the person gets the same ID back. After 30 frames it is removed.
  • Association cost in the first stage is 1 − IoU, additionally fused with the detection score (fuse_score: True), so confident detections are preferred.

6 · The skeleton as a graph

6.1 From pixels to 17 points

After stage 2 a person is no longer an image but a short list of keypoints: 17 points with an x, a y and a confidence. YOLOv8-pose and RTMPose both use the COCO order: nose, left and right eye, ear, shoulder, elbow, wrist, hip, knee, ankle. A person's pose in one frame is therefore 17 × 3 numbers, and in 24 frames 24 × 17 × 3.

6.2 Why a graph, and which graph

Intuition A sequence of skeletons is not a picture: the joints are not laid out on a grid, and the left elbow's real neighbours are the shoulder and the wrist, not whatever pixel happens to sit next to it. A graph says exactly who is whose neighbour. The 18 joints are the nodes, the bones are the edges.

verified in our code STG-NF does not use the 17-point layout directly. dataset.keypoints17_to_coco18 adds a neck joint as the average of the two shoulders and re-orders the points into the OpenPose-18 order that graph.py expects (opp_order = [0, 17, 6, 8, 10, 5, 7, 9, 12, 14, 16, 11, 13, 15, 2, 1, 4, 3], where 17 is the new neck). The edges of the “openpose” layout are (4,3) (3,2) (7,6) (6,5) (13,12) (12,11) (10,9) (9,8) (11,5) (8,2) (5,1) (2,1) (0,1) (15,0) (14,0) (17,15) (16,14), plus a self-link on every joint. That is 17 bones for 18 joints, so the skeleton graph is a tree centred on the neck: each hip hangs off its own shoulder (there is no hip-to-hip bone).

6.3 Normalising a pose

The same walk looks very different if the person is close to the camera or far away, left or right in the frame. We want the model to see the shape of the motion, not where in the image it happens. verified in our code data_utils.normalize_pose does, for every window:

  1. divide x by the frame width (856 by default) and y by the frame height (480);
  2. subtract the mean position over all joints and all 24 frames (so the motion is centred on its own average);
  3. divide x and y by the standard deviation of the y coordinate over all joints and frames: a body-height-like scale.
x̃ = (x/W − mean(x/W)) / std(y/H)     ỹ = (y/H − mean(y/H)) / std(y/H)

Two consequences. First, the model cannot tell a tall nearby person from a short faraway one, which is what we want. Second, where in the frame and how large the person is are gone: only the shape of the joint motion inside the window remains (legs swinging, arms raised, sudden changes of posture). Whatever STG-NF learns as “normal” is therefore a statement about body motion patterns, not about places.

7 · Graph convolution and ST-GCN

Intuition A convolution lets each pixel look at its neighbours. A graph convolution lets each joint look at its neighbours along the bones: “my new value is a weighted average of the values of the joints connected to me”. A temporal convolution lets each joint look at itself in neighbouring frames. Alternating the two gives a spatial-temporal graph convolutional network (ST-GCN) that can learn patterns like “the knee moves with the hip, in a rhythm of one step per half second”.

7.1 Graph convolution and the adjacency matrix

A graph convolution needs to know who is a neighbour of whom. That is stored in the adjacency matrix A (18 × 18): A[v, w] > 0 means joint v feeds into joint w. We normalise each column so that it adds up to 1, so the output is an average of the neighbours.

The math (verified in our code stgcn.py, graph.py) First a learned 1×1 convolution mixes the channels at every joint and frame (self.conv, kernel size 1 along time), then the average over the neighbourhood:
yc,t,w = Σv x′c,t,v · A[v, w]     (einsum('nkctv,kvw→nctw'))
Neighbourhood = all joints within max_hop bones of w, including w itself (self_link), each with weight 1 / (number of joints in the neighbourhood) (normalize_digraph).

7.2 A surprise: in STG-NF the graph is complete

Verified in code and by running graph.py STG-NF builds its graph with Graph(strategy='uniform', max_hop=max_hops) and the default max_hops = 8 (args.py; the released checkpoint's saved arguments do not list it, so the default applies, and with it our run reproduces the paper's 85.94 exactly, EXP-001). The longest path in the skeleton tree, e.g. from the left ankle up to the neck and down to the right ankle, is exactly 8 bones. So every joint is within 8 hops of every other and the adjacency matrix is the all-ones matrix, normalised: every entry is 1/18 = 0.0556.

In other words, in the released configuration the “graph” part of the graph convolution is global average pooling over joints, plus the learned channel mixing before it. The bone structure still matters for how we set up the problem (which joints exist, the neck hub) but not for the spatial averaging inside the network. verified in our code Set --max_hops 1 and the bones count again (try it in the slider above). We never changed this setting, and we have not measured what it would do to the AUC.

7.3 Temporal convolution

Along the time axis a normal 1-D convolution is used on each joint: Conv2d(C, C, (T_k, 1)) with Tk = T/2 + 1 = 13 frames (since temporal_kernel_size = None in the checkpoint's args, the code picks T // 2 + 1 with T = 24) and zero padding of 6 frames on each side so the output has 24 frames again.

7.4 The ST-GCN block as STG-NF uses it

verified in our code One st_gcn block does: 1×1 conv (channel mixing) → average over joints with A → BatchNorm → ReLU → temporal conv (13 × 1) → BatchNorm → add a residual → ReLU. In STG-NF's configuration (hidden_dim = 0) every coupling step uses one such block, taking 1 channel in and giving 2 channels out. The first flow step has no residual connection (first = True); all later ones have a small 1×1 conv + BatchNorm shortcut because the channel count changes (1 → 2). Its two output channels are not “features” for a classifier: they are the shift and the scale that an affine coupling layer applies to the other half of the data (section 8.4).

Counting the weights (verified in our code) One flow step: ActNorm 2 + 2 = 4, gcn 1×1 conv 1→2 (2 weights + 2 bias = 4), BatchNorm (4), temporal conv 2→2 × 13 (52 + 2 bias = 54), BatchNorm (4), residual conv + BatchNorm (4 + 4 = 8, absent in step 1). Step 1: 70; steps 2–8: 78 each. Total = 70 + 7 × 78 = 616, which matches the 616 weights quoted in EXP-001/EXP-019 and the released checkpoint (the checkpoint also stores BatchNorm running statistics and the fixed prior).

8 · Normalizing flows from zero, and STG-NF

The one-paragraph version Goal: given 24 frames of one person's motion, output how surprising it is compared with all the normal motion we trained on. To do that we need a model of “how common is each possible motion”, a probability density over the 864 numbers of a window. Writing down such a density for something this complicated is hard; drawing samples from a simple bell curve is easy. A normalizing flow connects the two worlds: it learns an invertible transformation that turns complicated normal motion into a perfectly simple cloud of independent bell-curve numbers. Because the transformation is invertible and we can track how much it stretches space, we can compute the exact probability density of any window. Surprising windows land in the thin tails of the bell curve (or come from a place where the transformation had to stretch a lot).

8.1 Probability density and surprise

A probability density is a curve whose total area is 1. It does not give the probability of one exact value (which is zero); the probability of landing in a small interval is the curve's height times the interval's width. Where the curve is high, values are common; where it is low, they are rare. The surprise of a value is −log p(x): small when p is high, large when it is low. This number, called the negative log-likelihood, is our anomaly score. The logarithm turns the product of many independent factors into a sum, which is what makes it practical for 864 numbers.

8.2 The core trick: change of variables

Intuition Imagine the number line as a rubber band printed with a lot of dots (data) and a histogram on top of it. If you stretch a part of the band, the dots there move apart and the histogram gets lower (same dots, more room). If you squeeze a part, the dots crowd and the histogram gets higher. The total area never changes. So if we know the shape of the histogram after the transformation (a plain bell curve) and we know how much we stretched at each place, we can compute the histogram before. A flow learns the stretching so that the “after” is a bell curve.
The math: the change-of-variables formula If z = f(x) with f invertible and increasing, and z has density pZ, then
pX(x) = pZ( f(x) ) · | f′(x) |    ⇔    log pX(x) = log pZ( f(x) ) + log | f′(x) |
f′(x) is the local stretch factor; log|f′| is the log-determinant. If you pick pZ as a standard bell curve then log pZ(z) = −½ z² − ½ log 2π is trivial, and the whole difficulty is moved into learning f. Because f is invertible (a bijection) we can go from data to z (scoring) and from z back to data (sampling).

8.3 Many dimensions: Jacobians, and why triangular is cheap

With 864 numbers instead of one, the stretch factor becomes a whole table of partial derivatives, the Jacobian, and the local volume change is its determinant: log pX(x) = log pZ(f(x)) + log|det Jf(x)|. A determinant of an arbitrary 864 × 864 table costs about 864³ operations, far too expensive to compute at every layer. Flows are designed so that the Jacobian is triangular (all entries above the diagonal are zero), and the determinant of a triangular table is just the product of its diagonal. The log of a product is a sum of logs: cheap.

The cleverest layer that produces triangular Jacobians is the affine coupling layer: leave half of the numbers alone and use them to decide how to stretch and shift the other half.

8.4 The three building blocks of STG-NF

A flow is a chain of layers; each one is invertible and reports its own log-determinant. The log-determinants are added up. STG-NF uses (code from modules_pose.py and model_pose.py, taken over from the Glow image flow) verified in our code:

(a) ActNorm: a learned per-channel scale and shift

Output = (x + b) · es for each channel, with learned b and s. The very first time it sees data (the first training batch) it sets b and s so that the output has mean 0 and variance 1 per channel (“data-dependent initialisation”), and afterwards they are ordinary trainable weights. Its log-determinant is Σ s · T · V: every one of the T×V = 24×18 positions in a channel is scaled by es.

(b) Permutation: reshuffle the channels

A coupling layer leaves half of the channels untouched. A permutation layer that comes before it changes which channels those are. The original Glow uses a learned invertible 1×1 convolution for this (InvertibleConv1x1, supported in the code, with a log-determinant from an LU decomposition), but the released ShanghaiTech checkpoint does not use it: its saved argument is flow_permutation = 'invcov', a typo for 'invconv'. In FlowStep.__init__ any value other than 'invconv' or 'shuffle' falls through to the last branch, which is a fixed reversal of the channel order (Permute2d(shuffle=False)). The checkpoint's state dict indeed holds no invconv weights. With only two channels (x and y) the reversal simply swaps x and y in every step, so consecutive steps alternate which coordinate is transformed and which one is the condition. Its log-determinant is 0 (a reordering does not change volume).

(c) Affine coupling with an ST-GCN inside

Forward (normal_flow) and inverse (reverse_flow), as in the code
z₁, z₂ = split(z)  (two halves of the channels)
(shift, raw) = ST-GCN(z₁)    scale = σ(raw + 2) + 10−6
z₂′ = (z₂ + shift) · scale    z₁′ = z₁    log det = Σ log(scale)
inverse:   z₂ = z₂′ / scale − shift

Why it is invertible: z₁ is passed through unchanged, so in the inverse we can recompute shift and scale from z₁′ = z₁ and simply undo the arithmetic. The network that produces shift and scale (here an ST-GCN, section 7) does not itself have to be invertible; it can be anything. Why it is cheap: the Jacobian is triangular, so the determinant is Π scale and log det = Σ log scale, one sum over the 1 × 24 × 18 = 432 scale values.

The scale is squashed to lie in (0, 1) by σ(raw + 2). At raw = 0 it is σ(2) = 0.88, so each step starts out close to the identity (slightly contracting) and learns from there. Because scale < 1 always, each step has a negative log-determinant.

8.5 STG-NF's exact stack

  • K = 8 flow steps, each = ActNorm → channel reversal → affine coupling with one ST-GCN block (1 → 2 channels). L = 1: the Glow-style multi-scale parts (SqueezeLayer for i > 1, and Split2d) exist in the code but are never used, so the tensor is (2, 24, 18) from start to end.
  • Prior. The base distribution is a bell curve with mean R = 3 and standard deviation 1 on each of the 864 numbers (prior_h_normal = [R, R, 0, 0] across the mean/log-std channels; the checkpoint stores exactly this). At test time every window is tagged “normal” (label = ones), so this normal prior is the one used. R mattered for the supervised UBnormal variants, where abnormal windows were pushed towards −R; for ShanghaiTech everything is normal, so the mean 3 is just a constant offset the flow aligns to.
  • 616 trainable weights, counted in section 7.4. (The model is tiny: that is why it runs in 0.7 ms.)

verified in our code One more detail that surprises people: with two channels, the coupling layer's “z₁” is only one channel (the x- or y-values of all 24 × 18 positions), and the ST-GCN reads all of it (all joints, all 13-frame neighbourhoods) to decide the shift and scale of the other channel at every position. That is where the spatio-temporal reasoning happens.

8.6 Training = make normal motion likely; scoring = how unlikely is this window?

Training. verified in our code Take windows of normal motion only (the ShanghaiTech training videos contain no anomalies; this is unsupervised or one-class learning). For each window, pass it through the flow, compute log p(x) = log pprior(z) + Σ log-dets and minimise its negative by gradient descent (maximum likelihood): the Adamax optimiser, learning rate 5e-4, batch size 256, 8 epochs, 24-frame windows every 6 poses, each shown as original and horizontal flip.

Scoring. verified in our code At test time the same quantity is computed for every window; the window's normality is −NLL (higher = more normal) and its anomaly score is the NLL. A window of motion unlike anything in training maps to z values far from the bell's centre, has low probability, and gets a high score. Section 9 turns window scores into frame scores.

8.7 Bits per dimension

The raw NLL grows with the number of numbers in the input. Bits per dimension divides by that number and converts nats to bits, so that values are comparable across models and datasets:

score = NLL / (ln 2 · C · T · V) = −( Σ log-dets + Σ864 log N(zi; 3, 1) ) / (ln 2 · 864)
verified in our code (STG_NF.normal_flow: nll = -objective / (math.log(2.0) * c * t * v).) A feel for the scale: a number that sits exactly on the prior's mean costs ½ ln 2π = 0.919 nats = 1.33 bits when the layer volumes do not change. our experiment The final-epoch training loss of our retrained standard models is 0.89 / 0.94 / 0.91 bits per dimension (EXP-019): a little below that reference.
Deeper dive: what a flow can and cannot do
  • Exact likelihood vs. other models. An autoencoder gives you a reconstruction error, a VAE only a bound on the likelihood, a GAN none. A flow gives the exact density, so a threshold on the score has a meaning.
  • High density is not the same as “normal”. from paper / docs Flows are known to sometimes assign high likelihood to data unlike the training data. STG-NF's model is tiny (616 weights), which limits this; but its notion of “unusual” is just “improbable under normal skeletons”, not “dangerous”.
  • Pose noise looks like an anomaly. our experiment In the dark, EXP-003 found that adding detections at a lower gate puts more (noisier) poses on normal frames, where STG-NF scores them as anomalous: more false alarms (L3 normal-frame coverage 0.465 → 0.487).
  • Bigger coupling networks did not help. our experiment Replacing the ST-GCN with a gated-attention-unit network (9.4× the weights) fitted the training set much better (−0.34 bits/dim vs 0.89) but did not improve the test AUC (−0.78 on released poses; EXP-019), consistent with overfitting; the authors did not test that explanation.

9 · From window scores to frame scores to AUC

9.1 Turning window scores into one score per frame

STG-NF gives one number per window (a person over 24 frames). The ground truth, however, says for every frame of the video whether something anomalous is happening. The code bridges the two with four rules verified in our code (scoring_utils.get_clip_score, re-implemented and tested against it in stgnf_eval.assemble_clip_scores):

  1. Where the window's score lands. On the frame start + 12 (the middle of a 24-frame window): the “paper” variant, which needs 12 future frames. Our live variant puts it on start + 23, the last frame, because only the past is available in a real deployment.
  2. Several people. The frame's score is that of the least normal person (the minimum of the normality, the maximum anomaly).
  3. Nobody there. A frame with no scored person gets the most normal score found anywhere in the dataset (the code starts with +∞ and replaces it by the largest finite normality). Nothing will be flagged there.
  4. Smoothing. The sequence of frame scores is blurred in time. The paper variant applies Gaussian filters of σ = 1, 2, 3, 4, 5, 6 one after another (equivalent to one Gaussian of σ ≈ 9.5 frames), which uses future frames. Our live variant uses a causal half-Gaussian over the current and past frames only (smoothing.py).

9.2 What AUC means

Intuition The pipeline gives each frame a number. We want to call a frame “anomalous” when the number is above some threshold. A low threshold flags every anomaly but also many normal frames (many false alarms); a high threshold has few false alarms but misses anomalies. The ROC curve plots this trade-off for every threshold at once: the fraction of anomalous frames caught (true-positive rate) against the fraction of normal frames wrongly flagged (false-positive rate). AUC is the area under that curve and has a very concrete reading: pick a random anomalous frame and a random normal frame; AUC is the chance that the anomalous one has the higher score. It does not depend on any one threshold.

Deeper dive: AUC as a rank statistic, and ties

Sort all frames by score. AUC is the average, over anomalous frames, of the fraction of normal frames ranked below them, with ties counted half. A pipeline that scores no person in many frames creates a large group of tied frames at the most-normal value, containing both normal and anomalous ones. Among the tied frames the ranking is a coin flip, and the anomalous frames in the tie can never beat the covered normal frames. That is the arithmetic behind “an undetected person is a guaranteed miss”. In the extreme case (nothing scored anywhere, e.g. 60%+ frames dropped on a slow device) all frames tie and AUC is exactly 0.5.

The same CLAHE that gains +3.15 at L2 (with noise) loses 1.49 without noise and 0.43 on clean frames; gamma hurts in moderate dark and helps only in deep dark; Zero-DCE++ is expensive: 100–190 ms per frame on a CPU against a 41.7 ms budget (EXP-004). Enhancement acts through the one channel that matters here, what reaches the detector (coverage), so it can only help where the detector is losing people for lack of contrast, and it cannot help where the people are already found or where nothing is left to see.

Two more dead ends, both consistent with “coverage, not model quality”: a bigger detector (YOLOv8s-pose) tracked fewer people at the default gate (coverage 0.569 vs 0.674) and scored lower (66.27 vs 68.53, EXP-007), and swapping STG-NF's coupling networks for bigger ones did not help (EXP-019, section 8.7).

The offline ranking of resolution is reversed by the deadline: 960 px is the best knob offline and the worst realistic one delivered. Cheap, condition-specific enhancers (CLAHE at moderate dark, gamma in deep dark) keep their whole gain because they cost 1–3 ms. Why does dropping frames hurt STG-NF so much? Three ways exist to cope with a gap:

  1. Skip and re-index (EXP-004/008): pretend the frames that were processed are consecutive. Windows are always complete, but their time axis is stretched (24 processed frames span 24/keep real frames), so motion looks unnaturally jerky to the flow, and tracks still break when the gap is long.
  2. Real-time indexing, no fill: windows are checked with is_seg_continuous (section 5.5); with a 40% or higher drop rate almost none pass and AUC is exactly 50 (EXP-009).
  3. Fill the missing poses by prediction (next section).

10.5 Pose filling: B and P

verified in our code fill.py (EXP-009/010) makes up the poses of frames that have none, before STG-NF sees the track, and keeps a separate sidecar file to remember which poses were made up. Two methods:

  • B (between): inside a gap of at most G missing frames between two detections, interpolate every keypoint linearly. It needs the next detection, so it is not causal.
  • P (predict): after every detection, extrapolate forward for at most G frames, stopping at the next detection. At step k the position moves by velocity × 0.8k, where the velocity is the change between the last two detections, and the keypoint confidence is multiplied by 0.8k. It is causal, so it adds no latency. Because 0.8 + 0.8² + … converges to 4, P can never move a joint further than about four frames' worth of velocity: it coasts and then freezes.

our experiment What it bought us:

  • Offline (no deadline), small but real: B with G = 8 raises 68.53 to 69.44 (+0.91, paired CI excludes 0) and P with G = 8 to 69.88 (EXP-009). The pre-registered guess that interpolation (B) beats extrapolation (P) was wrong: causal P is as good or better.
  • Under a real-time deadline it matters much more: filling vs skip-and-reindex gains +5.7 to +8.3 live AUC at 60% / 83% drops (five of six conditions significant, mean over twelve cells +5.65), including both detector sizes; it is not significant on UBnormal-8n and it cannot rescue a device that drops more than about 90% of frames (EXP-010). How blank frames are scored matters: scoring them “normal” instead of holding the last score gives +2.94 on average instead of +5.65; the authors treat the hold-last contrast as the like-for-like one, because the skip policy also holds its last score.
  • Not a free compute saver: running the detector only on every second frame and filling the rest loses 1.8–2.7 AUC (EXP-009 P3 fail).
  • Smarter variants did not beat plain filling: a filling-aware STG-NF (+C1) and a learned GRU filler (+C2) together scored −1.99 [−3.51, −0.29] against FILL-HOLD, with C2 alone +0.51 and C1 −2.45 (EXP-018).

10.6 What the findings add up to

The deployment rule from RESEARCH_SYNTHESIS.md
  1. Price every knob by delivered accuracy under the device's frame deadline, not by offline accuracy (resolution gains erode or reverse).
  2. Do not tune the confidence thresholds for low light.
  3. Monitor label-free person coverage as the health metric (it tracks AUC in the dark on both datasets).
  4. Treat illumination enhancement as a per-site, measured choice: no rule survived the second dataset.
  5. Pinning and co-load isolation help tail latency; never use SCHED_FIFO inside CPU-quota'd containers.

Open limits the authors state themselves: synthetic low light only, one main dataset (ShanghaiTech: 107 videos, wide confidence intervals), VM timing instead of Raspberry Pi timing, and an STG-NF checkpoint that was trained on AlphaPose-style poses.

Check yourself

Lowering the detector's confidence gate in the dark does not recover accuracy. Which statement matches the evidence?

EXP-003 H3: gate changes were at most +0.7 AUC (L3: −1.7). Lower thresholds add few usable tracks and more noisy poses on normal frames.

Why did 960 px, the best resolution offline, become the worst delivered at 24 fps?

Delivered accuracy is accuracy after the deadline: dropped frames create gaps that is_seg_continuous rejects.

Pose filling method P extrapolates with velocity × 0.8^k. Roughly how far can it move a joint, in total, however long the gap?

The geometric series 0.8 + 0.64 + 0.51 + … converges to 4, so P coasts and then freezes.

11 · Glossary

Every dotted-underlined term in the text links here. 87 entries, alphabetical.

ActNorm (activation normalisation) ¶
A flow layer that does y = (x + b)·es per channel, with b and s learned. They are initialised from the first batch so the output starts with mean 0 and variance 1. Its log-determinant is Σs · T · V (sum over channels, times the number of frames and joints). Section 8.
Adjacency matrix ¶
A square table A where A[v,w] says how strongly joint v feeds into joint w in a graph convolution. STG-NF row/column-normalises it so each column sums to 1.
Affine coupling layer ¶
Split the numbers in two halves. Leave half A alone; feed it to a small network that outputs a scale and a shift; apply them to half B: B′ = (B + shift)·scale. Trivially invertible and its log-determinant is Σ log scale. Section 8.4.
AlphaPose ¶
A heavier, accurate top-down pose estimator. The STG-NF authors used it (with a tracker called PoseFlow) to produce the pose files the released checkpoint was trained on. We call these the released poses.
Anchor-free detection ¶
Older detectors compared the image against hand-designed template boxes (“anchors”). YOLOv8 instead lets every grid cell predict distances from its own centre to the four sides of a box, so no templates are needed.
Anomaly score ¶
A number that is high when something looks unusual. In STG-NF it is the negative log-likelihood of a skeleton window (in bits per dimension); the code stores its negative as the “normality” score.
AUC (area under the ROC curve) ¶
A single number from 0 to 1 that says how well a score separates two groups. It equals the chance that a random anomalous frame gets a higher score than a random normal frame. 0.5 = coin flip, 1.0 = perfect. We report frame-level AUC × 100. Section 9.
Backbone ¶
The first part of a vision network: a stack of convolutions that turns pixels into feature maps at several resolutions.
Batch normalisation ¶
A layer that re-centres and re-scales each channel using the statistics of the current batch (and running averages at test time). It makes training stable. ST-GCN blocks use it; ActNorm is the flow-friendly cousin.
Bits per dimension ¶
The negative log-likelihood divided by (number of numbers in the input × ln 2). It puts the score in a unit that does not depend on how many numbers the input has. For STG-NF the input has 2 × 24 × 18 = 864 numbers.
Bootstrap confidence interval ¶
A way to see how much a result would wiggle with a different sample of videos: re-draw the 107 test videos with replacement many times, recompute the AUC each time, and report the middle 95% of the results. Our tables use 2000 (or 1000) resamples.
BoT-SORT ¶
A tracker: it follows each detected person from frame to frame and gives them a stable ID. It combines a Kalman filter, IoU matching with the Hungarian algorithm, a two-stage high/low-score association, and optional camera-motion compensation (GMC) and re-identification. Section 5.
Bounding box ¶
A rectangle around an object, stored as two corners (x1, y1, x2, y2) or as centre plus width and height.
C2f block ¶
YOLOv8's basic building block: split the channels, pass one half through a few small residual bottlenecks, and concatenate everything. Cheap and gradient-friendly.
Change-of-variables formula ¶
The rule that tells you how a probability density changes when you stretch or squeeze the axis: pX(x) = pZ(f(x)) · |f′(x)|. Heart of every normalizing flow. Section 8.
Channel ¶
One layer of numbers in a tensor, e.g. the red, green and blue tables of a colour image. In STG-NF the two channels are the x and the y coordinate.
CLAHE ¶
Contrast-Limited Adaptive Histogram Equalisation: a classic image-enhancement trick that stretches contrast separately in small tiles. One of the enhancers we tested for dark frames.
COCO (keypoints) ¶
A big public image dataset. Its person-keypoint version defines the 17-joint skeleton used by YOLOv8-pose and RTMPose: nose, 2 eyes, 2 ears, 2 shoulders, 2 elbows, 2 wrists, 2 hips, 2 knees, 2 ankles.
Confidence score ¶
A number between 0 and 1 that the network attaches to a detection or keypoint. It is not a calibrated probability; it is just a ranking signal that you compare to a threshold.
Convolution ¶
A small grid of learned weights (the kernel) slides over the image; at each position it multiplies and adds up the numbers underneath. The same weights are re-used everywhere, so a pattern is recognised wherever it appears. Section 2.2.
Coverage ¶
In this thesis: the fraction of frames (often: of the anomalous frames) in which at least one person ended up in a scored 24-frame window. A frame with no scored person cannot be flagged. Edge pipeline 0.674 vs released poses 0.965 on anomalous frames.
DFL (distribution focal loss) ¶
Instead of predicting one number for each box side, the YOLOv8 head predicts 16 scores over the distances 0…15 (in units of the stride) and takes the expected value. It makes the box edges easier to learn and gives a sense of uncertainty.
Feature map ¶
The output of a convolution layer: a stack of 2-D grids, one per channel, where each cell says how strongly some pattern is present around that position. Deeper maps are smaller (see stride) but each cell sees more of the image. Section 2.2.
FPN (feature pyramid network) ¶
A top-down path that upsamples deep (coarse, meaning-rich) maps and merges them with shallower (fine, detail-rich) maps, so every scale gets both. Part of the YOLOv8 neck.
Frame deadline ¶
At 24 frames per second a new frame arrives every 41.7 ms. If the pipeline is still busy, that frame is dropped. EXP-004 measures how often this happens on a CPU. Section 10.4.
Frame-level AUC ¶
The AUC computed over every single frame of every test video (40,791 ShanghaiTech test frames in 107 videos), each with its own label (normal/anomalous) and score.
Gaussian (normal) distribution ¶
The bell curve, fully described by a mean and a standard deviation. STG-NF's prior is a Gaussian with mean 3 and standard deviation 1 on every latent number.
GMC (global motion compensation) ¶
BoT-SORT can estimate how the camera moved between frames and shift its predicted boxes accordingly. We turn it off (gmc_method='none') because the replay has no images and the camera is static.
Gradient descent ¶
Training by repeatedly nudging every weight a little in the direction that reduces the loss. STG-NF's loss is the mean NLL; it uses the Adamax optimiser, a variant.
Graph ¶
A set of nodes (here: the 18 joints) plus edges (the bones). It is the natural way to say “which numbers are neighbours” when they are not on a regular pixel grid.
Graph convolution ¶
The graph version of a convolution: each node's new feature is a (weighted) combination of its neighbours' features, with weights from the adjacency matrix. Section 7.1.
Grid cell ¶
One position of a feature map. At stride 8 each cell stands for an 8×8 patch of the (resized) input, at stride 32 for a 32×32 patch.
Head (of a detector) ¶
The last part of a detector: small convolution stacks that read the feature maps and output, for every grid cell, the numbers that describe a person: box distances, a person score and the 17 keypoints. YOLOv8-pose has one head per scale (strides 8, 16, 32). Section 3.1.
Heatmap (keypoint) ¶
A small image per joint that is bright where the joint probably is. The joint is read off at the brightest cell, so the precision is limited by the heatmap's resolution. SimCC replaces it with two 1-D vectors.
Hop ¶
One step along a bone. Two joints are k hops apart if the shortest path between them has k bones.
Hungarian algorithm ¶
A method to pair up two lists (tracks and detections) so that the total cost of all pairs is as small as possible, instead of greedily taking the best pair first.
ID switch ¶
A tracker mistake: the same person gets a new ID, or two people swap IDs. The skeleton window of a person then stops or mixes two people.
imgsz (input size) ¶
The size the long side of the frame is resized to before entering the detector, e.g. 640 px. Our single biggest accuracy-for-compute knob.
Invertible 1×1 convolution ¶
A learned matrix that mixes the channels at every position. Invertible if the matrix is. STG-NF's code supports it, but the released checkpoint does not use it (see permutation).
Invertible map (bijection) ¶
A function that can be run backwards without losing information: every output comes from exactly one input. All flow layers must be invertible.
IoU (intersection over union) ¶
Overlap of two boxes: area of the part they share divided by the area they cover together. 0 = disjoint, 1 = identical.
is_seg_continuous ¶
The STG-NF function that decides whether a window is complete enough to be scored: at most missing_th = 2 of the 24 frames may be missing. Section 5.5.
Jacobian ¶
The table of all partial derivatives of a function's outputs with respect to its inputs. Its determinant says by how much the function stretches volume locally.
Kalman filter ¶
A recipe for combining a motion model (“it was moving this fast, so it should be here now”) with noisy measurements (“the detector says it is there”) in proportion to how much you trust each. Section 5.2.
Kernel (filter) ¶
The small grid of weights of a convolution, e.g. 3×3 numbers.
Keypoint ¶
A named point on the body, like the left wrist, stored as (x, y, confidence).
Latent variable ¶
The output of the flow, z. If the flow is good, z for normal data looks like a sample from the prior.
Letterboxing ¶
Resizing a frame to the network input without distorting it: scale so the long side fits, then pad the short side with grey bars. A 856×480 frame at imgsz 640 is scaled by 640/856 = 0.748.
Likelihood / log-likelihood ¶
How probable (dense) the model says the observed data is. We take the logarithm so that products of many small numbers become sums.
Log-determinant ¶
The logarithm of how much a layer stretches (>0) or squeezes (<0) volume. It is the bookkeeping term in the change-of-variables formula. For a triangular Jacobian it is just a sum of logs of the diagonal.
Maximum-likelihood training ¶
Choose the weights that make the training data as probable as possible. For STG-NF the training data are normal-motion windows only.
Neck ¶
The middle part of a detector that mixes feature maps from different scales (FPN + PAN) before the heads.
NLL (negative log-likelihood) ¶
−log p(x): the “surprise” of x under the model. Low for typical data, high for rare data. It is our anomaly score.
NMS (non-maximum suppression) ¶
After the network proposes many overlapping boxes for the same person, keep the best-scoring one and delete neighbours that overlap it by more than an IoU threshold, then repeat. Section 3.4.
Normalizing flow ¶
A model built from a chain of invertible layers that turns complicated data into a simple bell-shaped cloud. Because each layer is invertible and has a computable volume change, the exact density of any input can be computed. Section 8.
Oracle ¶
An experiment where we hand the pipeline part of the right answer (here: the boxes and tracks of the released poses) to see what the remaining part can do. EXP-015.
PAN (path aggregation network) ¶
A bottom-up path added after the FPN: it takes the fine-detail high-resolution maps and passes them back down to coarser levels with stride-2 convolutions.
Permutation layer ¶
A flow layer that only reorders channels. In the released STG-NF checkpoint it is a fixed reversal of the channel order. With two channels (x and y) it swaps them, so consecutive steps alternate which one is transformed.
Pose / skeleton ¶
The set of keypoints of one person in one frame.
Pose filling (P and B) ¶
Making up the poses of frames the detector missed or never saw. B interpolates between the detections before and after a gap; P extrapolates forward from the last detections, with damping 0.8. Section 10.5.
Prior (base distribution) ¶
The simple distribution the flow's output is compared to. Here: independent Gaussians N(3, 1). NLL is computed as the prior's log-density at z plus the accumulated log-determinants.
Probability density ¶
For a continuous quantity, the height of a smooth curve whose total area is 1. The probability of landing in a small interval is (height × width). Heights can exceed 1 when the curve is narrow.
Re-identification (ReID) ¶
Recognising a person again by appearance (a learned embedding of their image crop). BoT-SORT can use it; we switch it off.
Recall ¶
Of the people really present, the fraction the detector found.
ReLU ¶
The activation max(0, x).
Residual connection ¶
Add a layer's input to its output (y = F(x) + x) so that the layer only has to learn a correction.
ROC curve ¶
For every possible threshold on the score, plot the fraction of anomalous frames caught (true-positive rate) against the fraction of normal frames wrongly flagged (false-positive rate). Section 9.
RTMPose ¶
A fast top-down pose model from OpenMMLab: a CSPNeXt backbone and a small attention-based head that outputs SimCC vectors. We use the -t (tiny) and -s (small) variants. Details from the paper/docs.
Score smoothing ¶
The per-frame scores jump around, so STG-NF blurs them over time with Gaussians of sigma 1, 2, … 6 in turn (about one Gaussian of sigma 9.5 frames), which uses future frames. Our live variant uses a causal half-Gaussian that looks only at the past.
ShanghaiTech Campus ¶
A surveillance anomaly dataset: 13 fixed cameras on a campus, 856×480 frames, 107 test videos with anomalies such as bikes or running on footpaths. Our main benchmark.
Sigmoid ¶
σ(x) = 1/(1+e−x): squashes any number into (0, 1). Used for the keypoint visibility and for the flow's scale (σ(raw + 2) + 10−6).
SimCC ¶
“Simple Coordinate Classification”: instead of drawing a 2-D heatmap per keypoint, predict two 1-D score vectors (one over x positions, one over y positions) and take the highest. Section 4.2.
Single-stage (bottom-up) pose ¶
One network sees the whole frame and outputs people and their keypoints together (YOLOv8-pose).
Softmax ¶
Turns a list of scores into probabilities that add up to 1 by exponentiating and normalising.
SPPF ¶
A small block at the end of the backbone that max-pools the same map three times in a row and concatenates the results, so each cell sees a wider neighbourhood cheaply.
ST-GCN ¶
Spatial-temporal graph convolutional network: alternate a graph convolution over joints with a temporal convolution over frames. Section 7.
Stride ¶
How far the kernel jumps between positions. Stride 2 halves the width and height of the output. A feature map “at stride 8” is 8× smaller than the input in each direction.
Temporal convolution ¶
A convolution along the time axis only: each output frame is a weighted sum of a few neighbouring frames of the same joint. STG-NF uses 13 frames.
Tensor ¶
A multi-dimensional table of numbers: a vector is 1-D, an image 3-D (channels × height × width), and an STG-NF input is (channels, time, joints) = (2, 24, 18).
Threshold ¶
A cut-off on a score. Above it: flagged / kept; below: ignored.
Top-down pose ¶
First detect people (boxes), then crop each box and run a pose network on the crop. Section 4.
Track ¶
The sequence of detections that the tracker believes belong to one person, with one ID.
Track buffer ¶
How many frames a track may stay unmatched (“lost”) before it is deleted. BoT-SORT default: 30.
UBnormal ¶
A synthetic surveillance anomaly dataset with rendered people, including night and fog scenes. Our second dataset (EXP-006); near-chance AUCs for every arm.
Unsupervised (one-class) anomaly detection ¶
Train on normal data only, and call anything the model finds unlikely “anomalous”. No anomalous examples are shown during training.
Window (segment) ¶
24 consecutive poses of one tracked person: the unit STG-NF scores. Training windows start every 6 poses; at test time every pose starts one.
YOLOv8n-pose ¶
Ultralytics' nano (smallest) single-stage pose model: about the size that fits an edge CPU. 17 COCO keypoints per person.
